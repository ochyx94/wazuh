📊 Apa itu SIEM?

Security Information and Event Management

  • Sistem untuk mengumpulkan log dari semua sumber
  • Mengolah menjadi informasi keamanan
  • Membunyikan alarm saat ada yang mencurigakan

Satu tempat untuk melihat SELURUH keadaan keamanan.

😩 Masalah Tanpa SIEM

  • 50 server = 50 tempat cek log berbeda 😱
  • Format log beda-beda, tidak bisa dibandingkan
  • Serangan menyebar malam hari — siapkan begadang?
  • Bukti insiden tercecer / tertimpa rotasi log

Hasilnya: kejadian penting terlewat, respon lambat.

✅ Manfaat SIEM

  • Centralized — semua log di satu tempat
  • Search — cari kejadian dalam hitungan detik
  • Alerting — alarm otomatis saat pola berbahaya
  • Correlation — hubungkan kejadian dari banyak sumber

📜 Bonus: Compliance

SIEM juga membantu memenuhi regulasi & audit:

  • PCI-DSS — standar keamanan kartu pembayaran
  • ISO 27001 — manajemen keamanan informasi
  • GDPR / UU PDP — perlindungan data pribadi

Audit butuh bukti monitoring — log terpusat + alert = bukti.

📖 Fitur 2: Log Processing — Decoder

Decoder = penerjemah

  • Menerjemahkan log mentah → format terstruktur
  • Mengapa perlu? Format log tiap aplikasi beda-beda
  • Tanpa decoder: log hanya tumpukan teks

Analogi: penerjemah yang mengubah kalimat acak → data rapi.

⚙️ Cara Kerja Decoder (2 Fase)

Phase 1 — Pre-decoding

  • Ambil: timestamp, hostname, program_name
  • Pisahkan header dari isi log

Phase 2 — Decoding

  • Cocokkan dengan decoder yang dikenal
  • Ekstrak field: user, srcip, action, …

📜 Contoh Decoder XML (ssh)

<decoder name="sshd">
  <program_name>^sshd</program_name>
</decoder>

<decoder name="sshd-login">
  <parent>sshd</parent>
  <regex>Failed password for (\w+) from (\d+\.\d+\.\d+\.\d+)</regex>
  <order>user, srcip</order>
</decoder>

🔍 Membaca Decoder XML Itu

program_name ^sshd"log dari program sshd adalah milikku"
parentlanjutan dari decoder sshd
regexpola untuk menangkap data (\w+ = kata, \d+ = angka)
ordernama field hasil tangkapan, berurutan

Hasil: user=admin, srcip=192.168.1.100 — siap dipakai rule.

💡 Bonus OS_Regex: \p = punctuation · \l/\u = lower/upper · | = alternation · matching case-insensitive

⚖️ Apa itu Rules?

Rule = petugas penentu (aman / curiga / berbahaya)

  • Aturan deteksi dalam format XML
  • Logika: IF-THIS-THEN-ALERT
  • Menggunakan field hasil decoder, bukan teks mentah

Decoder membaca, rule memutuskan.

🧩 Elemen Rule Penting

idnomor unik rule (custom: 100000–120000)
leveltingkat severity 0–15
decoded_asmatch jika decoder tertentu cocok
fieldmatch nilai field hasil decoder
if_sidmatch jika rule induk juga match
frequency + timeframedeteksi kejadian BERULANG 🔁

📜 Contoh Rule XML

<rule id="100001" level="5">
  <decoded_as>sshd-login</decoded_as>
  <field name="action">failed</field>
  <description>SSH login failed</description>
  <group>authentication_failed,sshd,</group>
</rule>

Artinya: "decoder sshd-login cocok + action=failed → alert level 5"

🔁 Frequency Rule: Naikkan Severity

<rule id="100002" level="10" frequency="8" timeframe="120">
  <if_matched_sid>100001</if_matched_sid>
  <description>SSHD brute force attempt!</description>
</rule>

"8x gagal login dalam 2 menit dari IP sama → level 10!"

Inilah yang membedakan 1x salah ketik vs serangan brute force.

💡 Kurangi noise: <if_fts> = alert hanya untuk kombinasi field yang pertama kali muncul (mis. user baru pertama kali login).

📊 Alert Level Severity

Level 0tidak jadi alert (hanya dicatat)
Level 1–3informasi
Level 4–6rendah
Level 7–9sedang
Level 10–12tinggi
Level 13–15kritikal

🧠 Interpretasi Severity

1× gagal loginrendah mungkin salah ketik
8× gagal dari IP samatinggi indikasi brute force
Malware aktif terdeteksikritikal respons segera!

Severity = prioritas perhatian analyst.

⚡ Mini-Recap 3

  • Decoder membaca → data rapi
  • Rule memutuskan → alert / tidak
  • Severity menilai → seberapa serius
  • Frequency menaikkan level saat pola berulang

📁 Fitur 3: File Integrity Monitoring (FIM)

FIM = penjaga lemari arsip 🗄️

  • Memantau perubahan file: created, modified, deleted, renamed
  • Real-time alert saat file penting berubah

🦠 Perilaku Attacker yang Tertangkap FIM

  • Malware menulis file ke system directory
  • Persistence: ubah Run keys / buat scheduled task
  • Config change: ubah /etc/passwd, registry Windows

Attacker hampir selalu meninggalkan jejak file — FIM menangkapnya.

⚙️ Konfigurasi FIM di Wazuh

<syscheck>
  <directories realtime="yes">C:\Windows\System32</directories>
  <directories realtime="yes">/etc,/bin</directories>
  <registry>HKLM\SOFTWARE</registry>
</syscheck>

realtime="yes" = deteksi saat itu juga, tanpa menunggu scan.

🔎 Fitur 4: Vulnerability Detection (intro singkat)

  • Scan kelemahan sistem secara berkala
  • Daftar CVE, missing patches, outdated software
  • Proactive: cari lubang SEBELUM dipecahkan orang

Banding: FIM & alerting = reactive (setelah kejadian).

⭐ Attack 3: Brute Force SSH — Praktikum Uji Coba

Kita lakukan sendiri di lab — bukan menonton kasus orang lain.

🎯 TargetServer lab milik sendiri (Wazuh manager)
🎬 Peran kitaSebagai "penyerang" yang mencoba login SSH berkali-kali

⚠️ Semua pengujian HANYA ke server sendiri — menyerang sistem orang lain tanpa izin = ilegal.

🧪 Langkah Uji Coba — Bertahap

1️⃣ PersiapanPastikan Wazuh agent aktif & SSH service berjalan di target. Buka terminal di mesin penyerang.
2️⃣ Serangan sederhanaCoba login SSH salah password 3–5× manual:

3️⃣ Lihat di log serversudo grep "Failed password" /var/log/secure
4️⃣ Lihat di WazuhDashboard → Discover → filter rule.groups:authentication_failed
5️⃣ Level naik?Tambah frekuensi percobaan → amati rule frequency menaikkan severity

🎭 Level Lanjut: Ganti-Ganti IP (Distributed)

Penyerang sungguhan tidak pakai 1 IP — kita simulasikan dengan Tor:

1️⃣ Jalankan script lab (v3.5.0)./simulate_bruteforce.sh --host <ip> --count 5 --mode tor
5 IP berbeda via Tor · ringkasan terverifikasi log server
2️⃣ Gerbang etikaKetik SAYA PUNYA IZIN (pengingat: server milik sendiri!)
3️⃣ Amati outputSetiap iterasi = IP berbeda, login gagal, ringkasan terverifikasi log
4️⃣ Verifikasi servergrep "Failed password" /var/log/secure | tail -5 → IP-IP Tor berbeda
5️⃣ Di WazuhBanyak IP berbeda, 1–2 percobaan per IP = pola distributed brute force

🔍 Yang Diamati dari Alert

Rule yang terpicusshd: authentication failed (level 5)
Frequency ruleBanyak percobaan → naik ke level 10+ (group authentication_failures)
Field pentingsrcip (asal), dstuser (user dicoba), rule.firedtimes
Pola distributedBanyak IP berbeda × sedikit percobaan per IP = botnet, bukan manusia
MITRE ATT&CKT1110 Password Guessing / Brute Force

🚨 Handling Alert: JANGAN PANIK — 7 Langkah

  1. Baca description alert
  2. Cek severity level
  3. Identifikasi: user, source IP, host, waktu
  4. Cek apakah event berulang
  5. Bandingkan dengan aktivitas normal
  6. Putuskan: false positive atau insiden nyata?
  7. Ambil tindakan sesuai risiko

🛡️ Mitigasi Brute Force

Menangani alert dari praktikum

  • Hitung percobaan per IP → blokir agresif (firewall/fail2ban)
  • Cek login BERHASIL? → insiden! reset password

Mitigasi jangka panjang

  • SSH key, matikan password auth
  • Fail2ban / rate limiting
  • MFA admin · disable root login

Banyak alert = pertahanan BEKERJA — tetap verifikasi tidak ada yang lolos.
