📜 Contoh Decoder XML (ssh)

Sumber asli: 0310-ssh_decoders.xml — semua decoder bawaan Wazuh bisa dilihat di simulator.laptopexp.my.id/wazuh_builtin_decoders.json

<decoder name="sshd">
  <program_name>^sshd</program_name>
</decoder>

<decoder name="sshd-login">
  <parent>sshd</parent>
  <regex>Failed password for (\w+) from (\d+\.\d+\.\d+\.\d+)</regex>
  <order>user, srcip</order>
</decoder>

🔍 Membaca Decoder XML Itu

program_name ^sshd"log dari program sshd adalah milikku"
parentlanjutan dari decoder sshd
regexpola untuk menangkap data (\w+ = kata, \d+ = angka)
ordernama field hasil tangkapan, berurutan

Hasil: user=admin, srcip=192.168.1.100 — siap dipakai rule.

💡 Bonus OS_Regex: \p = punctuation · \l/\u = lower/upper · | = alternation · matching case-insensitive

⚖️ Apa itu Rules?

🗃️Field hasil decoder
→
⚖️RULE
IF-THIS-THEN-ALERT
→
🚨Alert

Decoder membaca, rule memutuskan. Format XML, pakai field — bukan teks mentah.

🧩 Elemen Rule Penting

idnomor unik rule (custom: 100000–120000)
leveltingkat severity 0–15
decoded_asmatch jika decoder tertentu cocok (mis. "log ini dari sshd")
fieldmatch nilai field hasil decoder
if_sidmatch jika rule induk juga match (rule "anak" dari rule lain)
frequency + timeframedeteksi kejadian BERULANG 🔁

📜 Contoh Rule XML

<rule id="100001" level="5">
  <decoded_as>sshd-login</decoded_as>
  <field name="action">failed</field>
  <description>SSH login failed</description>
  <group>authentication_failed,sshd,</group>
</rule>

Artinya: "decoder sshd-login cocok + action=failed → alert level 5"

🔁 Frequency Rule: Naikkan Severity

<rule id="100002" level="10" frequency="8" timeframe="120">
  <if_matched_sid>100001</if_matched_sid>
  <description>SSHD brute force attempt!</description>
</rule>

"8x gagal login dalam 2 menit dari IP sama → level 10!"

Inilah yang membedakan 1x salah ketik vs serangan brute force.

💡 Kurangi noise: <if_fts> = alert hanya untuk kombinasi field yang pertama kali muncul (mis. user baru pertama kali login).

📊 Alert Level Severity

Level 0tidak jadi alert (hanya dicatat)
Level 1–3informasi
Level 4–6rendah
Level 7–9sedang
Level 10–12tinggi
Level 13–15kritikal

🧠 Interpretasi Severity

1× gagal loginrendah mungkin salah ketik
8× gagal dari IP samatinggi indikasi brute force
Malware aktif terdeteksikritikal respons segera!

Severity = prioritas perhatian analyst.

⚡ Mini-Recap 3

  • Decoder membaca → data rapi
  • Rule memutuskan → alert / tidak
  • Severity menilai → seberapa serius
  • Frequency menaikkan level saat pola berulang

📁 Fitur Wazuh: File Integrity Monitoring (FIM)

🗄️File Penting
arsip sistem
→
🦠Attacker
created / modified / deleted / renamed
→
🚨Real-time Alert

FIM = penjaga lemari arsip 🗄️ — real-time alert saat file penting berubah.

🦠 Perilaku Attacker yang Tertangkap FIM

  • Malware menaruh file di folder sistem Windows
  • Persistence (cara attacker "nempel" agar aktif setelah restart): ubah daftar program auto-start Windows
  • Ubah config: ubah daftar user Linux / pengaturan Windows

Attacker hampir selalu meninggalkan jejak file — FIM menangkapnya.

⚙️ Konfigurasi FIM di Wazuh

<syscheck>
  <directories check_all="yes" realtime="yes">C:\Users\NAMA_KAMU\Downloads</directories>
  <directories check_all="yes" realtime="yes">C:\Users\NAMA_KAMU\Desktop</directories>
  <directories check_all="yes" realtime="yes">C:\Users\NAMA_KAMU\Documents</directories>
  <ignore type="sregex">\.tmp$|\.log$|\.crdownload$</ignore>
</syscheck>

Ganti NAMA_KAMU dgn username Windows-mu. realtime="yes" = deteksi saat itu juga. Config ini disimpan di ossec.conf agent.

🔍 Cara FIM Mendeteksi

📸1. Baseline
scan pertama: catat "kamus" semua file — ukuran, waktu, hash (MD5/SHA1/SHA256)
→
👁️2. Pantau realtime
Windows API tahu langsung saat file dibuat/diubah/dihapus
→
⚖️3. Bandingkan
attribute file sekarang vs kamus — beda? itu kejadian
→
🚨4. Alert ke Manager
rule 554 file added · 550 file modified · 553 file deleted

💬 Cek di agent setelah config: C:\Program Files (x86)\ossec-agent\queue\diff\ berisi baseline FIM → syscheck aktif.

🛠️ Persiapan: Aktifkan PowerShell Logging

Sekali saja sebelum praktikum — agar setiap command PowerShell tercatat di Event Viewer. ("Script Block Logging" = fitur bawaan Windows yang merekam perintah PowerShell) (Event 4104).

1️⃣ Buka Group Policy EditorTekan Win + R → ketik gpedit.msc → Enter
2️⃣ Navigasi ke menuComputer Configuration → Administrative Templates → Windows Components → Windows PowerShell
3️⃣ Aktifkan loggingKlik 2x "Turn on PowerShell Script Block Logging" → pilih Enabled → OK
4️⃣ Update policyWin + R → ketik cmd → Enter → ketik gpupdate /force → Enter
5️⃣ Selesai ✅Lanjut ke Langkah Attack 2 (PowerShell)

📌 Komputer kantor/domain: minta bantuan IT admin jika gpedit tidak tersedia.

🎯 Konsep VISIBILITY (ketahuan apa yang diketik)

Ketik command di PowerShell → tercatat di Event Viewer (Event 4104) → agent kirim ke Wazuh → muncul di Dashboard

Command yang dicoba: ping · ipconfig · whoami · dir

Pelajaran: attacker mengetik sesuatu — dan SEMUANYA meninggalkan jejak.
